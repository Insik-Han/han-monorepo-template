# Internationalization (Lingui)

`apps/web` and `apps/native` are internationalized with [Lingui](https://lingui.dev) v6.
This document covers the repo-specific setup; generic Lingui API usage follows the
official docs (macros from `@lingui/react/macro` and `@lingui/core/macro`).

## Locales

- `sourceLocale`: `en` (all source strings are written in English)
- Shipped locales: `en`, `ja`, `ko`
- Each app has its own `lingui.config.ts` and its own catalogs:
  - web: `apps/web/src/shared/i18n/locales/{locale}/messages.po`
  - native: `apps/native/shared/i18n/locales/{locale}/messages.po`

## Build integration (do not mix up the two apps)

| App    | Macro transpilation                                                                                                                                                        | Catalog loading                                                                                                                           |
| ------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| web    | `@rolldown/plugin-babel` with `@lingui/babel-plugin-lingui-macro` in `vite.config.ts` (note: `reactCompilerPreset()` belongs in `presets`, the Lingui plugin in `plugins`) | `@lingui/vite-plugin` compiles `.po` on import; `en` is loaded eagerly in `src/shared/i18n/i18n.ts`, `ja`/`ko` via dynamic import         |
| native | `babel.config.js` (`babel-preset-expo` + `@lingui/babel-plugin-lingui-macro`)                                                                                              | `@lingui/metro-transformer/expo` in `metro.config.js` compiles `.po` in-bundle; all locales import synchronously in `shared/i18n/i18n.ts` |

There is no separate `lingui compile` step — both bundlers compile catalogs.
After changing `babel.config.js` or `metro.config.js`, restart Metro with `expo start --clear`.

## Workflow when adding or changing UI strings

1. Write the string in English with a macro:
   - JSX text → `<Trans>...</Trans>` (`@lingui/react/macro`)
   - attributes / non-JSX strings → `const { t } = useLingui()` (`@lingui/react/macro`), then `` t`...` ``
   - module-level constants → `` msg`...` `` (`@lingui/core/macro`), resolved at render time
   - On native, keep `<Trans>` inside the existing styled `<Text>`; the app-level
     `I18nProvider` already sets a `<Text>` `defaultComponent` as a fallback.
2. Add a translator `comment` for short or ambiguous strings (location, purpose,
   part of speech). Never put complex expressions inside a message — extract to a
   named variable first.
3. Re-extraction is automatic on commit: the `vp staged` pre-commit hook
   (`staged` block in the root `vite.config.ts`) runs the touched app's
   `i18n:extract` and stages the updated catalogs into the same commit as
   your source change. To extract manually, run `vp run i18n:extract` in the
   app directory you touched (or at the repo root for both apps via turbo).
4. Fill in the new `msgstr` entries in `ja/messages.po` and `ko/messages.po`.
   Keep placeholders (`{name}`), tags (`<0>...</0>`) and ICU syntax intact.
   Rule: no empty `msgstr` besides the header entry. This is NOT machine-checked
   (CI only re-extracts; empty `msgstr` survive extraction unchanged) — verify
   it in review when catalogs change.
5. `vp check` must stay green.
6. CI runs `vp run i18n:extract` on every PR (the `i18n-extract` job in
   `.github/workflows/ci.yml` — Lingui v6 has no `extract --check`; direct
   pushes to `main` skip the job). If the catalogs change, the job writes the
   diff to its run Summary page and fails — CI holds no write permissions; it
   never pushes or comments. Fix it locally: run `vp run i18n:extract`,
   translate any new `msgstr` entries, and commit the result. Catalogs are
   extracted without
   `#: file:line` references (`lineNumbers: false` in `lingui.config.ts`), so
   unrelated source edits do not churn them.

## Runtime conventions

- Locale state lives in `shared/i18n` of each app (FSD `shared` layer); the
  switcher UI is the `features/locale` slice (`LocaleSelect` on web, `LocaleToggle`
  on native).
- Detection: web = `localStorage("locale")` → `navigator.languages` → `en`;
  native = SecureStore `"locale"` → device locale (`expo-localization`) → `en`.
- Do not translate: brand names, URLs, CSS classes, `name`/`id` attributes,
  currency/locale codes, sample data (names, emails).
